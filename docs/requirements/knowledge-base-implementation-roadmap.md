# 团队知识库 App 实施路线图

- 日期：2026-08-04
- 输入规范：`knowledge-base-app-design.md`
- 原则：每个阶段都必须产出可以独立验证的软件；上一阶段未通过门禁，不进入下一阶段。

## 为什么拆成多个实施计划

产品包含 Apple 客户端、云端权限与存储、异步文件解析、语义搜索和内测发布五类工作。把它们放进一个超大计划会让接口、依赖和验收边界变得模糊，因此按风险和依赖顺序拆为五个阶段。

## 阶段 0：技术可行性验证

详细计划：`knowledge-base-phase-0-technical-validation-plan.md`

验证内容：

- Tauri 2 + React 工程能够运行于 Mac 和 iPhone 模拟器。
- iPhone 分享扩展能够把 PDF 复制进 App Group，宿主应用能够读取队列。
- PostgreSQL/pgvector 能够对中文自然语言查询返回相关文件。
- 形成明确的 Go/No-Go 结论和下一阶段输入。

门禁：三项验证全部通过；若任意一项失败，先调整技术路线，不搭建完整产品。

## 阶段 1：云端基础与安全边界

独立交付：可测试的 Supabase 专用云端开发环境和数据库迁移。

范围：

- Auth、Workspace、Membership、File、FileVersion、ProcessingJob、ContentChunk 和 Device 数据模型。
- Row Level Security、成员邀请和移除。
- Storage 私有桶、签名上传与下载地址。
- 文件状态机、审计事件和跨团队隔离测试。

门禁：跨团队读取、搜索、下载和更新均被数据库拒绝；迁移可以在一次性 Supabase Branch 或独立空白云端项目中完整重建。

## 阶段 2：文件处理与混合搜索

独立交付：从对象存储读取文件并产出可搜索片段的异步处理服务。

范围：

- 任务幂等、重试、部分成功和版本原子切换。
- PDF、Word、PPT、Excel、图片、扫描件和网页适配器。
- OCR、文本标准化、来源位置和向量生成。
- 语义召回、全文关键词召回、文件聚合和固定评测集。

门禁：固定解析样本无回归；30～50 个真实问题的 Recall@5 不低于 80%。

## 阶段 3：Mac 与 iPhone 客户端

独立交付：两端可以完成登录、上传、查看状态、搜索、预览和打开原文件。

范围：

- 搜索工作台和“全部资料”页面。
- Mac 拖拽、批量上传、文件夹监听和离线队列。
- iPhone 分享扩展、待上传队列和系统通知。
- 文件筛选、命中片段和来源位置。

门禁：核心端到端流程在 Mac 和 iPhone 均通过；断网恢复和重复事件不会产生重复版本。

## 阶段 4：集成、稳定性与小团队内测

独立交付：可以交给 2～10 人连续使用的签名内测版本。

范围：

- 完整端到端与权限回归。
- 5,000 文件规模下的搜索性能验证。
- 崩溃监控、处理任务监控、备份和恢复演练。
- Mac 签名构建和 iPhone 内测分发。
- 两人试用与小团队内测反馈闭环。

门禁：无权限隔离缺陷；搜索性能和质量达到规范；备份恢复演练成功。

## 计划生成规则

- 阶段 0 现在生成详细计划。
- 阶段 1～4 的详细计划在上一阶段通过后生成，因为它们需要使用上一阶段真实产出的目录、接口、工具版本和验证结论。
- 每份计划继续采用测试先行、短步骤、独立验收和明确回滚边界。
- 未获得用户明确授权前，不执行 `git init`、`git add`、`git commit`、推送或发布。

## 规范覆盖映射

| 设计规范章节 | 实施阶段 |
|---|---|
| 产品目标与首版成功标准 | 阶段 0 验证技术门槛；阶段 2 验证搜索质量；阶段 4 验证规模与真实使用 |
| 账号、团队、角色和邀请 | 阶段 1 云端权限；阶段 3 客户端界面 |
| Mac/iPhone 资料导入与状态 | 阶段 2 处理契约；阶段 3 客户端与系统集成 |
| PDF、Office、OCR、网页处理 | 阶段 2 文件处理服务 |
| 语义搜索、关键词、聚合与来源 | 阶段 0 检索可行性；阶段 2 完整搜索；阶段 3 结果界面 |
| 同步、离线队列、文件夹监听与通知 | 阶段 3 客户端；阶段 4 稳定性验证 |
| 数据模型、版本切换与删除清理 | 阶段 1 数据基础；阶段 2 处理流程 |
| 错误处理 | 阶段 1 状态机；阶段 2 任务重试；阶段 3 客户端恢复；阶段 4 故障演练 |
| 安全与隐私 | 阶段 1 RLS 与签名地址；阶段 4 安全发布门禁 |
| 测试策略 | 每个阶段的独立门禁；阶段 4 完整端到端回归 |
| 发布策略 | 阶段 4 |
| 明确不做的功能 | 所有阶段共同约束，不创建对应模块、入口或数据模型 |
