# Phase 3 文件状态摘要设计

本阶段在当前团队文件列表上增强处理状态表达。目标是让用户不用逐行扫描，也能快速知道当前团队资料是否仍在处理、是否已有可搜索内容、是否存在失败项。

## 范围

- 在文件列表头部显示状态摘要。
- 显示文件总数。
- 显示待处理数量：`awaiting_upload`、`pending_processing`、`processing`。
- 显示可搜索数量：`searchable`、`partially_searchable`。
- 显示失败数量：`failed`。
- 显示最后刷新时间。
- 文件行状态标签增加状态类型样式。

## 非范围

- 不做实时订阅。
- 不做轮询。
- 不做处理失败重试。
- 不做删除、预览、下载。
- 不新增云端接口。

## 数据流

1. `useFiles` 成功读取当前团队文件后记录 `lastRefreshedAt`。
2. `FileListPanel` 基于当前 `files` 计算状态摘要。
3. 点击“刷新”继续使用已有 `refreshFiles()`。
4. 上传成功或重复后沿用已有回调刷新列表。

## 测试

- helper 测试覆盖状态统计。
- App 级测试覆盖文件列表展示摘要和最后刷新时间。
