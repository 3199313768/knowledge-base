# 全客户端 shadcn/ui 迁移设计

## 目标

将知识库客户端从当前混合的自定义控件与页面样式迁移为统一的 Oxygen Design System 组件体系，并以平衡型界面密度覆盖登录、应用壳层、搜索、上传、文件列表、文件详情、团队和回收站。

本轮以 UI 结构、视觉规范、响应式和可访问性为范围，保留现有认证、Supabase、工作区、搜索、上传、文件处理和回收站业务行为。

## 已确认方向

- 采用全客户端 Oxygen Design System 迁移，而不是仅做 CSS 规范化。
- 使用平衡型密度，兼顾 Mac 上的工作效率和 iPhone 上的可触达性。
- 保留当前冷灰背景、中性白面板和稳定蓝色主操作的产品气质。
- 基础组件由独立私有包 `@oxygen-design/ui` 提供；该包内部使用 shadcn/ui 模式、Radix Primitives 和 Lucide。
- 不提交、不推送、不部署，不覆盖当前工作区内已有的未提交修改。

## 范围

### 包含

- 登录、注册、会话读取、认证错误和当前设备退出。
- 桌面侧栏、移动导航、账号菜单和页面容器。
- 搜索、搜索历史、搜索结果和对应状态。
- 单文件与批量上传、空文件区拖放上传和结果反馈。
- 文件状态筛选、选择、批量操作、文件列表和文件详情。
- 团队列表、团队创建表单、回收站和删除确认。
- 加载、空数据、错误、成功、禁用、处理中和权限不足状态。
- Mac 与 iPhone 共用语义组件的响应式布局。

### 不包含

- 修改 Supabase 客户端配置、认证协议、数据库策略或存储规则。
- 修改搜索、上传、文件处理、批量操作和回收站的业务契约。
- 新增找回密码、第三方登录、邀请接受或全设备退出。
- 引入新的全局业务状态容器。
- 云端 RLS、Storage、后台处理或真实数据环境的发布验收。
- 暗黑模式；本轮只建立可扩展的语义颜色变量。

## 架构

### 基础 UI 层

独立私有包 `@oxygen-design/ui` 是共享基础 UI 层。知识库不长期维护另一套同名基础组件。共享包提供：

- `Button`
- `Input`
- `Card`
- `Badge`
- `Alert`
- `Checkbox`
- `AlertDialog`
- `DropdownMenu`
- `Tabs`
- `Sheet`
- `Tooltip`

共享包采用 shadcn/ui 的源码内置方式，使用 `cn` 合并类名，并使用 CVA 管理需要变体的组件。共享包的详细边界、分发和发布规则见 `docs/superpowers/specs/2026-10-26-oxygen-design-system-package-design.md`。

Radix Primitives 负责弹窗、菜单、标签页、抽屉和提示的键盘交互、焦点管理与可访问性语义。Lucide 负责搜索、上传、文件、刷新、删除、重试、菜单、显示密码等图标，不继续维护字符图标或页面内零散 SVG。

### 业务组件层

`apps/client/src/components` 保留业务语义，只组合 `@oxygen-design/ui` 组件和消费稳定的服务 hook。业务组件不得重新定义按钮、输入框、徽标、弹窗、菜单或标签页的基础尺寸和状态。

页面入口和 `App.tsx` 继续只负责应用级 provider、认证视图选择和页面组合，不承载复杂表单、数据转换或交互细节。

### 数据流边界

现有服务和 hook 的职责保持不变：

- 认证通过统一 auth 服务和 `useAuthSession`。
- 工作区通过 workspace 服务和 `useWorkspaces`。
- 搜索及历史记录通过对应 service 和 hook。
- 上传、文件列表、重试、删除和批量操作继续通过现有 service 和 hook。
- 回收站继续遵守当前恢复、永久删除和清理状态契约。

UI 层只消费稳定状态和回调，不直接创建 Supabase client，也不展示 Supabase 原始错误、SQL、token、请求头或堆栈。

## 依赖与配置

知识库新增运行依赖 `@oxygen-design/ui`，并从包入口导入 React 组件及一次性导入 `@oxygen-design/ui/styles.css`。Radix、CVA、Lucide、Tailwind 构建和 shadcn 源码由独立 UI 仓库维护，不在知识库中重复安装和维护。

迁移前先通过真实 tarball 验证包的类型、CSS 和生产构建，再发布并改用私有 npm 精确版本。具体接入顺序见共享包设计文档。

## 视觉系统

### 间距

使用 `4px` 基础网格：

- 紧密元素：`4px`
- 图标与文字、相邻控件：`8px`
- 表单内部和紧凑区块：`12px`
- 常规组件内部：`16px`
- 页面内容与主要区块：`24px`
- 大区块分隔：`32px`
- 页面级最大留白：`48px`

不得为单个页面发明新的任意间距值。响应式变化只在布局层调整。

### 排版

- 正文：`14px / 20px`
- 辅助文字：`12px / 18px`
- 表单标签：`13px / 20px`
- 区块标题：`16px / 24px`
- 页面标题：桌面 `24px / 32px`，手机 `20px / 28px`

字体沿用系统无衬线字体栈。字号不随视口宽度缩放，不使用负字距。长文件名、邮箱、团队名称和状态文本必须换行或省略，不能撑破容器或遮挡其他内容。

### 控件尺寸

- 桌面端输入框、按钮和选择器：`40px` 高。
- iPhone 端主要操作和图标按钮：至少 `44px` 触控高度。
- 常规图标：`16px`。
- 主要操作图标：`18px`。
- 图标按钮：固定正方形尺寸，布局不随加载文案变化。
- 登录面板：桌面最大宽度 `420px`，手机使用可用全宽并保留 `16px` 外边距。

### 圆角、边框和阴影

- 卡片与对话框：`8px` 圆角。
- 输入框与按钮：`6px` 圆角。
- 徽标、状态筛选和头像可使用胶囊或圆形。
- 默认边框为中性灰细边框。
- 阴影只用于弹窗、抽屉或需要建立层级的浮层；页面区块不通过大阴影制造悬浮卡片。

### 颜色

颜色通过 Oxygen 语义令牌管理：

- 冷灰页面背景。
- 中性白内容面板。
- 深中性色正文和较浅的辅助文字。
- 稳定蓝色主操作与焦点环。
- 绿色成功状态。
- 琥珀色处理中或警告状态。
- 红色错误与破坏性操作。

界面不能用单一蓝色表达所有状态，也不能只依赖颜色传达成功、错误、禁用或处理中状态。

## 布局与响应式

### 应用壳层

应用外层改为全屏工作界面，不再作为一个带大圆角和阴影的悬浮卡片。

- 桌面侧栏约 `240px`，主内容区域自适应。
- 主内容桌面内边距 `24px`，平板 `20px`，手机 `16px`。
- 文件工作台充分使用宽屏，不强制套用窄内容最大宽度。
- 文件列表与详情栏在桌面形成两栏，详情栏约 `360px`。
- 页面区域使用无框布局，仅文件项、对话框和确实需要边界的工具使用卡片。
- 禁止卡片嵌套卡片。

### 移动端

Mac 和 iPhone 使用同一套业务组件。

- 侧栏在手机端替换为顶部栏和 `Sheet` 导航。
- 工具栏允许换行，但主要操作保持完整且不被压缩。
- 文件工作台变为单列；文件详情通过 `Sheet` 展示，避免横向压缩。
- 表单、错误提示和操作按钮不得被虚拟键盘或安全区域遮挡。
- 页面不能横向溢出，长文字不能覆盖前后内容。

## 页面与组件设计

### 登录页

- 使用 `Card`、React Hook Form、`Input`、`Button` 和 `Alert`。
- 密码显示切换使用带 tooltip 和可访问名称的 Lucide 图标按钮。
- 保留登录、注册、邮箱确认、会话重试和当前设备退出流程。
- 提交期间禁用字段和重复提交，显示稳定的中文加载文案。

### 应用导航

- 桌面使用固定侧栏，手机使用顶部栏和 `Sheet`。
- 账号信息收进 `DropdownMenu`。
- 当前团队入口清晰可见并可进入团队页面。
- 退出动作明确为“退出当前设备”。

### 搜索

- 搜索框和按钮组成固定高度的命令区。
- 搜索历史使用紧凑标签，支持选择、清空、加载失败和重试。
- 搜索结果使用可扫描的结果列表，不能用多层卡片堆叠。
- 保留空查询、请求重叠、工作区切换和未知文件结果的现有保护。

### 上传

- 普通工作台使用主按钮触发文件选择。
- 无文件状态使用虚线拖放区域，不再额外嵌套卡片。
- 单文件和批量上传保留现有结果反馈和重复文件处理。
- 上传中禁用重复提交，并提供可感知的处理中状态。

### 文件列表和状态中心

- 使用语义列表和稳定的 CSS 网格列，不新增复杂表格库。
- 使用 shadcn `Checkbox` 选择文件，使用 `Badge` 显示状态。
- 状态筛选使用 `Tabs`，统一“全部、处理中、可搜索、失败”等入口。
- 批量操作位于列表工具栏，运行期间禁用冲突操作。
- 文件名、更新时间、状态和大小在桌面保持稳定列宽，在手机自然换行。

### 文件详情

- 桌面显示右侧检查器，手机显示 `Sheet`。
- 元数据、预览、重试和删除分区展示。
- PDF 与 DOCX 保留现有不同预览流程和安全错误文案。
- 删除统一使用 `AlertDialog`，不使用浏览器原生确认框或自定义遮罩。

### 团队页面

- 团队列表和创建表单分开，避免将所有内容放进一个大卡片。
- 创建表单使用 React Hook Form，覆盖空值校验、提交中、失败和成功后的状态复位。
- 当前团队状态通过文字和图标共同表达。

### 回收站

- 使用统一列表行展示文件名、删除时间、到期时间和操作。
- 恢复与永久删除具有清晰的状态和禁用规则。
- 永久删除使用 `AlertDialog`。
- 保留 `cleanup_pending` 等真实业务结果，不把后台清理尚未完成显示为已完成。

### 占位和状态页面

- “最近使用”和“设置”等未完成页面使用克制的空状态。
- 空状态说明当前没有什么以及下一步可执行动作。
- 不使用营销式大标题、装饰性插画或大型悬浮卡片。

## 状态与错误处理

所有远程数据区域必须覆盖：

- `loading`
- `empty`
- `error`
- `success`
- `disabled`
- `submitting` 或 `processing`
- 权限不足

服务层继续负责底层错误分类。组件层只显示稳定中文文案，并在可恢复时提供“重试”“返回”或“重新登录”等动作。

Radix 组件负责弹窗和菜单的键盘操作、焦点锁定、Escape 关闭与关闭后的焦点恢复。表单错误通过 `aria-invalid` 和 `aria-describedby` 关联，动态状态通过 `role="status"`、`role="alert"` 或 `aria-live` 表达。

## 样式组织

样式拆为三个层次：

1. 主题基础：由 `@oxygen-design/ui` 提供的颜色变量、字号、圆角和组件样式。
2. 应用布局：应用壳层、侧栏、内容区、工作台网格和响应式断点。
3. 业务页面：搜索、上传、文件列表、文件详情、团队和回收站的语义布局。

基础控件的状态和尺寸只存在于 `@oxygen-design/ui`。迁移完成后删除知识库中已被共享包取代的旧按钮、输入框、卡片、徽标、确认遮罩和字符图标样式，避免两套规范并存。

## 迁移顺序

1. 在独立仓库完成并验证 `@oxygen-design/ui` 首批组件和模式。
2. 使用真实 tarball 在知识库完成消费 smoke test。
3. 发布并安装私有 npm 精确版本。
4. 迁移登录页及认证状态。
5. 迁移应用壳层、桌面侧栏、移动导航和账号菜单。
6. 迁移工作台、搜索、上传、文件状态和文件列表。
7. 迁移文件详情、删除确认和移动详情抽屉。
8. 迁移团队页面、创建表单和回收站。
9. 删除本地重复基础组件和旧样式，完成响应式、可访问性和视觉验收。

每一步先更新或补充测试，再迁移实现。每一步都必须保留用户当前未提交修改，并检查本步 diff 是否包含无关改动。

## 测试与验收

### 自动化检查

- 基础组件测试覆盖变体、禁用态、键盘操作和焦点行为。
- 登录和团队创建表单覆盖校验、提交中防重、错误恢复和成功状态。
- 弹窗覆盖取消、确认、重复操作防护和焦点恢复。
- 搜索、上传、状态筛选、文件选择、批量操作和文件详情保留现有行为测试。
- App 集成测试覆盖登录进入工作台、搜索打开文件、上传刷新列表、选择文件显示详情和删除进入回收站等链路。

完成后运行：

```bash
pnpm --dir apps/client test:unit
pnpm --dir apps/client typecheck
pnpm --dir apps/client build
git diff --check
```

### 浏览器验收

启动真实 Vite 页面，在桌面和 iPhone 视口验证：

- 登录、注册、密码显示、错误、加载和提交中状态。
- 桌面侧栏、移动导航和账号菜单。
- 搜索、搜索历史、搜索结果和错误恢复。
- 单文件与批量上传、拖放和重复文件反馈。
- 文件筛选、选择、批量操作、详情、预览、重试和删除。
- 团队创建与切换。
- 回收站恢复和永久删除确认。
- 文字溢出、横向滚动、控件遮挡、触控尺寸、键盘焦点和弹窗层级。

组件测试通过不等于页面验收通过。最终报告必须分别说明自动化检查、真实浏览器验证和未执行的云端集成验证。

## 验收标准

1. 整个客户端使用 `@oxygen-design/ui` 提供的统一基础组件、通用模式和语义主题变量。
2. 页面间距、字号、控件高度、圆角、颜色和状态符合本设计基线。
3. 不再存在页面级手写按钮、输入框、弹窗、菜单、标签页或确认遮罩。
4. Mac 和 iPhone 共用语义组件，布局无横向溢出、文字重叠或操作遮挡。
5. 所有远程区域具备完整的加载、空数据、错误、成功和处理中状态。
6. 认证、搜索、上传、文件操作、团队和回收站业务行为不因迁移发生改变。
7. 关键交互支持键盘、可见焦点和屏幕阅读器语义。
8. 客户端单元测试、TypeScript 检查、生产构建和 diff 检查通过。
9. 桌面与 iPhone 的真实浏览器关键流程完成验证。
10. 当前未提交修改得到保留，且未执行提交、推送、部署或云端数据变更。

## 与登录页设计的关系

`docs/superpowers/specs/2026-10-26-login-page-visual-refresh-design.md` 仍记录登录页已经确认和部分实现的行为。本设计将其纳入全客户端迁移，并作为后续 UI 实现的上位设计。若两份文档在基础组件、尺寸或布局方式上冲突，以本设计为准；认证行为仍以登录页设计和现有测试为准。

## 与共享包设计的关系

`docs/superpowers/specs/2026-10-26-oxygen-design-system-package-design.md` 定义独立仓库、公共 API、样式隔离、Storybook、Changesets 和私有 npm 发布规则。本设计只定义知识库如何消费共享包和迁移业务页面。若两份文档在共享组件所有权或发布方式上冲突，以共享包设计为准。
