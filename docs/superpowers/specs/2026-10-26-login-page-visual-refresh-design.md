# 登录页视觉优化设计

## 目标

将现有登录页优化为克制、专注的 macOS 工具风格，减少模板感和开发阶段信息，同时保留全部现有认证行为。

## 已选方案

采用“专注单面板”布局：全屏冷灰背景上居中放置一个紧凑的认证面板。页面不加营销介绍、插画、大面积渐变或多层卡片，使用户可以直接完成登录或注册。

已比较但未选用的方案：

- 工具双栏：品牌表达更强，但对高频登录来说信息过多，小屏还需额外的布局变体。
- 账户设置表单：系统感和安全感较强，但视觉偏正式，与当前知识工作台的轻量感不如单面板一致。

## 视觉与布局

- 页面使用冷灰纯色背景，不使用装饰性渐变、光斑或模糊色块。
- 认证面板桌面端宽度约为 `420px`，最大宽度不超过屏幕可用空间；使用细边框、小圆角和轻量阴影。
- 面板顶部展示简化的知识库标识与“知识库”名称，移除“Phase 3”开发阶段文案。
- 登录模式标题为“欢迎回来”，说明为“登录后继续查找和整理团队资料。”
- 注册模式标题为“创建账号”，说明为“使用邮箱和密码创建账号，用来登录团队资料。”
- 字段标签保持在输入框上方；输入框和主按钮高度为 `42–44px`，使用清晰的聚焦环、禁用态和提交中状态。
- 主操作使用稳定蓝色；字段、边框和辅助文字使用中性灰，不让页面被单一蓝色主导。
- 登录和注册切换放在表单底部，以一行可执行文案呈现。

## 响应式

- Mac 和 iPhone 复用同一套语义组件，不拆成两个页面。
- 小屏上页面外边距缩小，面板占满可用宽度；内容不得横向溢出或被虚拟键盘遮挡。
- 在矮屏上优先保证表单和主操作可见，不使用固定屏幕高度强制居中。

## 组件边界

- `App.tsx` 继续只选择加载、认证和工作台视图，不增加表单细节。
- `AuthCard.tsx` 负责认证模式、表单校验、提交状态、服务错误与邮箱确认提示。
- 认证页复用 `components/ui` 中的 `Button`、`TextInput` 和 `Card`，不继续手写同类基础控件。
- 新增认证页专用的 CSS 类仅描述布局和业务语义；通用按钮、输入框和卡片状态继续由共享样式管理。

## 表单实现

按项目约定引入 `react-hook-form`，使用它管理邮箱、密码、同步校验和提交状态。当前依赖中没有可以替代的表单状态工具；继续使用多个 `useState` 会违反项目对登录表单的明确约定。

本轮不更改认证服务契约、Supabase 客户端配置或会话生命周期。

## 状态与错误

- 会话读取中：在相同页面背景和面板框架中显示“正在读取当前设备会话…”，并使用 `aria-live` 通知状态。
- 字段校验失败：在对应字段附近显示中文错误，同时保持可感知的错误语义，不仅依赖颜色。
- 提交中：主按钮显示“正在登录…”或“正在创建…”，并禁用表单重复提交。
- 认证服务失败：保留完整表单，在表单上方显示安全的中文错误与“重试”操作。
- 注册需邮箱确认：保留现有确认提示，不自动跳转或隐藏表单。
- 已有会话且强制显示认证页：保留“退出当前设备”操作，不实现全设备退出。

## 测试与验证

- 组件测试使用 role、label 和可见文案选择器，不依赖 CSS class 或 DOM 层级。
- 覆盖登录、注册切换、必填校验、密码长度校验、提交中防重、认证失败、邮箱确认提示和会话重试。
- 运行认证页相关 Vitest、客户端 TypeScript 检查和客户端构建。
- 在实际开发服务器中验证桌面和 iPhone 宽度，检查文字溢出、控件遮挡、聚焦、错误和提交中样式。

## 不在范围内

- 找回密码、第三方登录、邀请接受、全设备退出。
- 修改 Supabase 配置、认证服务或数据库策略。
- 重设主工作台、导航、上传或搜索页面。
- 新增图片素材、自定义字体或新的全局状态容器。

## 验收标准

1. 未登录时显示已确认的“专注单面板”视觉，不再显示“Phase 3”。
2. 登录、注册、退出当前设备、会话重试和邮箱确认行为与优化前一致。
3. 表单使用共享 UI 组件和 React Hook Form，提交期间不能重复提交。
4. 桌面和 iPhone 宽度下都无水平溢出、文字重叠或主操作遮挡。
5. 加载、字段错误、服务错误、成功提示和禁用状态都有可读的中文文案与可访问语义。
6. 认证页相关测试、客户端 TypeScript 检查和客户端构建通过。
